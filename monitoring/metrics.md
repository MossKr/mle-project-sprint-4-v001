# Метрики мониторинга

## Офлайн-метрики модели (считаются при обучении, логируются в MLflow)

| Метрика | Описание |
|---|---|
| `recall@10` | Доля тестовых товаров, попавших в топ-10 рекомендаций |
| `precision@10` | Точность в топ-10 |
| `map@10` | Mean Average Precision@10 |

Метрики логируются при каждом запуске DAG-а в MLflow-эксперимент `retailrocket_recsys`. Деградация >10% от базового recall — сигнал для ручной проверки.

## Сервисные метрики (отправляются из `app.py`)

| Метрика | Описание |
|---|---|
| `requests_total` | Общее число запросов к сервису |
| `cold_start_ratio` | Доля ответов из top_popular (нет истории пользователя) |
| `recommendation_latency_ms` | Время ответа на запрос рекомендаций |
| `event_ingestion_total` | Число принятых событий через POST /events |

Метрики экспортируются в формате Prometheus через `/metrics` (если подключить `prometheus-fastapi-instrumentator`). Пример подключения:

```python
from prometheus_fastapi_instrumentator import Instrumentator
Instrumentator().instrument(app).expose(app)
```

## Бизнес-метрики (офлайн, считаются по логам)

| Метрика | Описание |
|---|---|
| CTR рекомендаций | Кликов по рекомендованным товарам / показов |
| Конверсия из рекомендации в addtocart | addtocart после клика по рекомендации |
| Доля холодных пользователей | % визитов от пользователей без истории |

## Мониторинг дрейфа данных

При каждом запуске DAG логирует:
- число строк в events.csv (резкий рост или спад — признак проблемы с пайплайном)
- распределение типов событий (сдвиг addtocart/transaction ratio)

Всё это пишется как MLflow-метрики в тот же ран.
